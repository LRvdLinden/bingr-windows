# Bingr voor Windows: werkafspraken

- Deze repo is de Windows-app van Bingr: een lichte schil (Tauri v2, WebView2) rond de webspeler op https://bingr.online/web/ (repo LRvdLinden/bingr-website, map `web/`). De app laadt de live webspeler; functies van de speler zelf (inloggen, servers, Live TV, films, series, sync) horen in bingr-website, niet hier. Hier alleen wat Windows-specifiek is: venster, offline-melding, volledig scherm, mediatoetsen, links naar de browser, installer en ondertekenen.
- Openbare repo: geen geheimen, persoonsgegevens of logs met servergegevens in bestanden, commits of workflow-logs. Secrets alleen als GitHub-secrets (zie README.md).
- Versie en build staan in `version.properties` (`BINGR_VERSION`, `BINGR_BUILD`); daarna `python3 tools/set_version.py` (zet ze in `src-tauri/tauri.conf.json` als `1.0.1+140`, `Cargo.toml`/`Cargo.lock` en `package.json`; de workflow controleert dat met `--check`).
- Buildnummers zijn één doorlopende reeks met de andere apps: een nieuwe build krijgt het volgende vrije nummer (hoogste build in `docs/changelog.json` van LRvdLinden/iptv-ios-appletv + 1). Alleen verhogen als de Windows-app echt verandert; wat niet verandert, krijgt geen nieuwe build. Een wijziging aan alleen de webspeler is een `web`-build in bingr-website, geen Windows-build.
- Bij elke build:
  - Een item in `docs/changelog.json` van iptv-ios-appletv met platform **`windows`** (alleen de punten die echt voor de Windows-app gelden; "Alle apps" omvat vanaf build 140 ook `windows`).
  - Daar `python3 tools/make_changelog.py --windows ../bingr-windows` draaien en `CHANGELOG.md` hier committen **vóór** (of samen met) het ophogen van de build: de workflow haalt de release-notities voor het beheer uit de sectie `Build <n>`.
  - Daarna de stappen van iptv-ios-appletv (o.a. `tools/sync_website.py`), zodat de build op bingr.online/changelog staat.
- Buildpakketten (de installer `.exe`, ook een `.msi` of zip) **nooit** op GitHub: niet in een repo, niet als release, niet als (onversleuteld) artefact. De workflow *Build* levert ze alleen versleuteld aan bij de **privé** repo LRvdLinden/bingr-inbox (`tools/seal_build.sh` uit bingr-beheer, anoniem gekloond; platform `windows`; secret `BINGR_INBOX_TOKEN` met alleen Contents: write op bingr-inbox, nooit in een URL). De workflow *Builds* van bingr-beheer zet ze in de afgesloten map `builds/` op de server; downloaden alleen via het beheer (tab Downloads, kortgeldige link). Ontbreekt `BINGR_INBOX_TOKEN`, dan niets aanleveren (::notice::, wel groen). Nooit een schrijftoken op bingr-beheer in deze repo.
- GitHub Actions vast op een commit-SHA (tag als commentaar). Versies van Tauri en plugins liggen vast in `Cargo.lock` en `package-lock.json`.
- Ondertekenen alleen via secrets (Azure Artifact Signing of een .pfx, zie README.md); zonder secrets onondertekend met een ::notice::. Certificaten, wachtwoorden en `metadata.json` nooit in de repo of in een log.
- Na elke push: `gh run list -R LRvdLinden/bingr-windows` (workflow *Build* geslaagd), en binnen 15 minuten *Builds* in bingr-beheer (annotatie "windows build <n> op de server gezet"). De logboeken staan op de branch `ci-logs` (`latest.txt`, `build.log`, `smoke.log`, `screenshot.png`).
- Commitberichten in het Nederlands.
